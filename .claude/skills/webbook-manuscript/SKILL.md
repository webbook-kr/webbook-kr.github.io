# 웹북 원고 변환

## 이 스킬이 하는 일

자료 하나를 받아서 **웹북 제작기의 "원고 (마크다운)" 칸에 그대로 붙여넣을 수 있는 텍스트**를 만든다.

제작기는 이 원고를 읽어서 표지, 차례, 장 표지, 본문 쪽, 마지막 쪽을 자동으로 조립한다. 그러니까 원고에는 **본문만** 쓴다. 표지나 차례를 직접 쓰면 중복으로 들어간다.

## 작업 순서

### 1. 원문을 끝까지 읽는다

요약부터 하지 말고 전체를 본다. 어디가 핵심이고 어디가 곁가지인지 알아야 장을 나눌 수 있다.

파일이 길면 나눠 읽되, 건너뛰지 않는다. 읽지 않은 부분을 지어내면 책 전체의 신뢰가 무너진다.

### 2. 뼈대를 먼저 잡는다

본문을 쓰기 전에 장과 쪽 목록을 만든다.

- 장(`#`)은 **3~7개**. 원문이 짧으면 3개, 길면 7개까지.
- 각 장에 쪽(`##`)은 **2~6개**.
- 전체 쪽 수는 20~50쪽이 읽기 좋다. 100쪽이 넘으면 장을 합치거나 내용을 덜어낸다.

장 제목은 내용을 말해 주는 문장으로. "1부", "개요", "서론" 같은 빈 제목은 독자에게 아무것도 알려 주지 않는다.

### 3. 쪽 단위로 옮긴다

**한 쪽에 한 가지 생각.** 이게 이 책 형식의 전부다. 독자는 손가락으로 넘기면서 읽는다. 한 쪽에 세 가지가 들어 있으면 넘길 때마다 머리가 무겁다.

제작기는 한 쪽이 **대략 900자**를 넘으면 자동으로 쪼개고 제목 옆에 "(계속)"을 붙인다. 자동 분할은 문장 중간을 끊지는 않지만, 의미 단위를 무시하고 자른다. 그러니 **한 `##` 안을 300~700자로 유지**해서 자동 분할이 일어나지 않게 쓰는 게 좋다.

글자 수를 셀 때 표, 그림, 영상도 자리를 차지한다는 걸 기억한다. 표 한 줄은 글자 70자쯤, 그림 하나는 420자쯤, 영상 하나는 380자쯤으로 계산된다. 표가 큰 쪽에는 설명을 길게 붙이지 않는다.

### 4. 검산한다

원고를 다 쓰고 나서 `scripts/check.mjs` 를 돌린다. 이게 이 스킬에서 가장 중요한 단계다.

```
node <스킬폴더>/scripts/check.mjs 원고.md
```

제작기와 똑같은 규칙으로 장과 쪽을 세고, 제작기가 못 알아듣는 표기를 줄 번호와 함께 찍어 준다. 눈으로 세는 것보다 빠르고 안 틀린다. **문제가 나오면 고치고 다시 돌린다.** 깨끗해질 때까지 반복한다.

노드(Node.js)를 못 쓰는 환경이면 아래를 손으로 확인한다.

- `#` 장 제목 다음 줄에 **빈 줄을 두고** `##` 를 썼는가 → **장마다 빈 쪽이 한 장씩 생긴다.** 붙여 쓴다.
- `###` 이하 제목을 썼는가 → 제작기가 못 알아듣는다. `## `로 올리거나 `**굵게**`로 바꾼다.
- `*한 별표*` 이탤릭을 썼는가 → 지원 안 된다. `**두 별표**`로 바꾼다.
- 목록을 들여쓰기로 겹쳐 놨는가 → 한 단계만 된다. 평평하게 편다.
- 표지, 차례, 목차, "끝" 쪽을 직접 썼는가 → 지운다. 자동으로 생긴다.
- 900자 넘는 `##` 구간이 있는가 → 나눈다.

빈 쪽 문제는 눈에 잘 안 띄면서 책 전체를 허술해 보이게 만든다. 보통 마크다운은 제목 뒤에 빈 줄을 넣는 게 관례라서 무심코 쓰면 그대로 걸린다. 그래서 이렇게 쓴다.

```
# 장 제목
## 첫 쪽 제목

본문 시작.
```

### 5. 내보낸다

`웹북-원고.md` 같은 이름으로 파일에 저장하고, **대화창에도 코드 블록으로 함께 보여 준다.** 휴대폰에서 파일을 열기보다 화면에서 바로 복사하는 게 빠를 때가 많다.

파일 위에는 제작기 입력칸에 넣을 값을 짧게 적어 준다.

```
책 제목: 마크다운을 붙여넣으면 책이 됩니다
글쓴이: 작가
부제: 5분이면 전자책 한 권
```

## 웹북 마크다운 문법

### 뼈대

| 쓰기 | 결과 |
|---|---|
| `# 장 제목` | 새 장. 장 표지 쪽이 생기고 차례에 오른다 |
| `## 쪽 제목` | 새 쪽. 제목이 쪽 위에 붙는다 |
| `---` | 제목 없이 쪽만 나눈다 |

### 본문

| 쓰기 | 결과 |
|---|---|
| `**굵게**` | 굵은 글씨 |
| `` `코드` `` | 코드 글씨 |
| `> 인용` | 인용 상자 |
| `::: 한 줄` | 메모 상자. 짧은 당부나 주의에 쓴다 |
| `- 항목` | 글머리 목록 |
| `1. 항목` | 번호 목록 |
| `\| 칸 \| 칸 \|` | 표 |
| ` ```코드``` ` | 코드 덩어리 |
| `[글자](주소)` | 링크 |
| `![설명](그림주소)` | 그림 |
| `youtube: 영상ID` | 눌러야 재생되는 영상 |

### 세미나·강연·영상 정리용

| 쓰기 | 결과 |
|---|---|
| `발표자: 이름 \| 소속 \| 시간` | 발표자 정보칸 |
| `핵심: 한 줄` | 결론 강조 상자 |
| `Q: 질문` 다음 줄 `A: 답변` | 질의응답 카드 |
| `Q: 질문 -- 이름` | 말한 사람 표시 |
| `12:30 내용` | 시간 목차. 누르면 영상이 그 지점부터 |
| 문장 속 `(37:20)` | 글 안의 시간 링크 |

`youtube:` 로 영상을 넣은 쪽에서만 시간 링크가 영상을 움직인다. 영상 없이 시간만 쓰면 그냥 표시만 된다.

### 안 되는 것

`###` 이하 제목, `*이탤릭*`, 겹친 목록, 각주, 체크박스는 지원하지 않는다. 그대로 글자로 나온다.

## 글 쓰는 법

읽는 사람은 대개 50대 이상이거나 바쁜 직장인이다. 전문 용어를 아는 사람이 아니라 **시간을 아끼고 싶은 사람**이다.

- 한 문장 한 뜻. 문장이 길어지면 자른다.
- 전문 용어는 쉬운 비유로 먼저 설명하고 용어를 붙인다.
- 영어는 한글 발음을 같이 적는다. 예: 마크다운(Markdown), 슬러그(slug)
- 따뜻하게. "어렵지 않아요", "천천히 해도 됩니다" 같은 말이 사람을 붙잡는다.
- 과장하지 않는다. 안 되는 건 안 된다고 쓴다. 정직이 이 책의 무기다.

원문에 없는 사실을 만들어 넣지 않는다. 자료가 비어 있는 부분은 비워 두고, 무엇이 빠졌는지 사용자에게 알려 준다.

## 자료 종류별 요령

자료가 무엇이냐에 따라 뼈대 잡는 방법이 다르다. 해당하는 것만 읽는다.

`references/sources.md` — PDF·워드, 파워포인트, 유튜브 영상과 자막, 세미나 녹취, 블로그·메모 뭉치를 각각 어떻게 장과 쪽으로 옮기는지.

## 딸린 도구

`scripts/check.mjs` — 원고 검산기. 4단계에서 쓴다. 장·쪽 수를 세고 못 읽는 표기를 찾는다. 제작기의 쪽 나눔 규칙을 그대로 옮겨 놨으므로 여기서 나온 쪽 수는 실제 책과 같다.

## 예시

**원문 (강의 슬라이드 3장 분량)**

> 슬라이드 1: AI 자동화란 무엇인가 / 반복 업무를 기계가 대신하는 것
> 슬라이드 2: 엑셀 자동화 사례 / 매출 정리 3시간 → 5분
> 슬라이드 3: 시작하는 법 / 가장 지겨운 일 하나를 고르세요

**원고**

```
# 자동화가 뭔지부터
## 기계가 대신할 수 있는 일

매일 같은 순서로 하는 일이 있습니다. 파일을 열고, 숫자를 옮기고, 저장하고.

이런 일은 사람이 하지 않아도 됩니다. 순서가 정해져 있으니까요.

::: 판단이 필요한 일은 여전히 사람 몫입니다.

# 실제로 줄어든 시간
## 매출 정리 3시간이 5분으로

| 전 | 후 |
|---|---|
| 3시간 | 5분 |

**한 달에 60시간**이 남습니다. 하루가 아니라 이틀 반입니다.

# 오늘 시작하려면
## 가장 지겨운 일 하나만

핵심: 전부 바꾸려 하지 말고 하나만 고르세요.

- 매주 반복되는 일인가
- 순서가 늘 같은가
- 하고 나면 지치는가

셋 다 해당하면 그게 첫 번째입니다.
```

장마다 한 가지 이야기, 쪽마다 한 가지 생각. 이 리듬이 지켜지면 원고는 이미 책이다.
